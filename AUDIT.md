# PeaBox IDE — Audit & Remediation (v0.15.0)

This document records the issues found in the 0.14.x codebase and how 0.15.0
addresses them. It is deliberately explicit about what is verified and what is not.

## Verification status

- **Static checks**: `npm run validate` (syntax via `node --check`, DOM ids, icon
  names, preload/IPC channel parity, CSP and Electron security flags).
- **Unit tests**: `npm run test:unit` (`node --test tests/unit.test.js`) covers the
  shared helper module.
- **End-to-end**: `npm run test:e2e` (Playwright) launches the real Electron app.

**Results from this remediation pass** (portable Node 26, Electron 38.8.6):

- `tools/validate.js`: passed — 117 DOM ids, 36 icons, 51 IPC handlers.
- `tests/unit.test.js`: 15/15 passed.
- `tests/electron.spec.js`: passed — boot, nested-folder regression, Monaco editor,
  workspace search, theme toggle, settings modal, command palette, explorer file
  creation + save, native open-file flow, and a **live node-pty terminal** that
  echoed a marker typed through xterm.js.
- The shipped `node-pty` prebuilt binary (`prebuilds/win32-x64`) loads and spawns a
  real shell inside Electron 38.8.6 without a source rebuild, so no Visual Studio
  C++ toolchain is required. `tools/postinstall.js` probes this before attempting a
  rebuild.
- `npm run build` produced `dist\PeaBox-IDE-0.15.0-Windows-x64.exe` (portable) and
  `dist\PeaBox-IDE-0.15.0-Windows-x64.zip`.
- A packaged smoke test launched `dist\win-unpacked\PeaBox IDE.exe` and verified
  boot, Monaco, the preload API and a live terminal running from
  `app.asar.unpacked`, so the build is not just source-verified.
- `package-lock.json` is generated by `npm install`; commit it for reproducible CI.

## Critical defects fixed

### P0 — Opening any folder with a subfolder crashed the explorer

`renderer.js` flattened the tree with a recursive `flatten(nodes, a)` that read
`n.children`, but `listDir()` in the main process only returned `{name,path,dir}`.
Any directory containing a child directory threw
`TypeError: for...of requires an iterable value, received undefined`.

**Fix**: the tree is now rendered lazily and structurally. `appendNodes()` recurses
only over arrays returned by `workspace:children`; children are fetched on expand
and cached in `S.treeCache`. The nested `tests/fixture/src/deep/leaf.js` file is a
permanent regression fixture for the E2E test.

### P0 — Command injection through Git operations

Branch names, file paths and remote names were interpolated into a shell string.

**Fix**: every Git call now goes through `spawn('git', [args...], { shell: false })`
with `GIT_TERMINAL_PROMPT=0`, `GIT_PAGER=cat` and `GIT_ASKPASS=echo`. Branch names
are validated with `PB.validateBranchName`, which allows `/` (e.g. `feature/login`)
while rejecting Git-invalid sequences.

### P0 — Renderer could read/write arbitrary files

The old preload exposed raw `ipcRenderer` and the main process trusted any path.

**Fix**:
- `contextBridge` exposes a fixed, namespaced API only.
- `assertAllowed()` resolves paths with `realpath`, then confines them to registered
  workspace roots (plus files explicitly created via a native dialog or recovery).
- `assertWorkspaceDir()` applies the same rule to run/terminal working directories.
- `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`,
  `webviewTag: false`.
- `setWindowOpenHandler` denies new windows; `will-navigate` and
  `will-attach-webview` are blocked; all permission requests are denied.
- A strict CSP is set in `index.html`.

## Runtime integration defects caught by the E2E pass

- **Renderer never booted.** Declaring `const api = window.api` at classic-script
  top level collided with the non-configurable global created by `contextBridge`,
  throwing `Identifier 'api' has already been declared`. The renderer is now wrapped
  in an IIFE, which also keeps helpers out of the global scope.
- **AMD loader conflict.** xterm/addon-fit UMD bundles register anonymous AMD
  modules. Loading them after Monaco's loader produced
  `Can only have one anonymous define call per script file`. The bundles now load
  before Monaco's loader, so they attach their globals normally.
- **Monaco workers under `file://`.** Language workers cannot fetch relative
  scripts from a `file://` origin. An inert blob worker is supplied; editing,
  highlighting and Monaco's main-thread features work, while worker-backed
  IntelliSense is intentionally not advertised.

## Data-loss and reliability fixes

- **Atomic saves**: `write-file-atomic` with `fsync` replaces direct `writeFile`.
- **Save race guard**: `entry.saving` / `entry.pendingSave` prevent overlapping
  writes; version checks keep `dirty` accurate if the buffer changes mid-save.
- **Recovery**: debounced snapshots to `userData/recovery`, keyed by path hash,
  pruned after 30 days, offered on startup and cleared after a successful save.
- **External changes**: per-file watchers distinguish unmodified files (auto
  reload), dirty files (Keep Mine / Reload), and deletions (tab marked deleted).
- **Folder rename/delete guards**: operations that would orphan open buffers are
  refused with an explanation.
- **Session restore**: last workspace, open files, active file, Git message, panel
  and sidebar sizes persist through `state.json` / `window.json`.
- **Window bounds** are validated against current displays so a disconnected
  monitor cannot hide the window.

## Security hardening summary

| Area | Before | After |
| --- | --- | --- |
| Renderer isolation | Node integration / raw IPC | Sandbox + context isolation + namespaced bridge |
| Path handling | Trusted strings | `realpath` confinement to opened roots |
| Git execution | Shell string interpolation | Argument arrays, `shell: false` |
| Navigation | Unrestricted | `will-navigate` blocked, `window.open` denied |
| Permissions | Default | All denied |
| CSP | None | `default-src 'self'`, `script-src 'self'` (no inline scripts, no `unsafe-eval`) |
| Process control | `taskkill` on string | PID-based tree kill |

## Performance and scalability

- Directory listing is per-folder and cached; expanding a folder no longer walks
  the whole tree.
- Workspace search and file indexing run in the main process with `setImmediate`
  yields, a 20 s deadline, a 2 MB per-file cap and a NUL-byte binary check.
- Global file index is capped at 25,000 entries and invalidated on watcher events.
- Git refresh is debounced and coalesced (`S.gitBusy` / `S.gitPending`).
- Terminal panes are fitted only when visible and on resize.

## UX improvements

- Command palette (`Ctrl+Shift+P`) and fuzzy quick open (`Ctrl+P`).
- Custom modals and confirmations replace the unsupported `window.prompt()`.
- Toast notifications, keyboard-navigable context menus, breadcrumbs.
- Full Git surface: branch select/create, staged/unstaged groups, per-file actions,
  diff views, commit, pull/push, stash/pop.
- Multi-session terminal with tabs and error surface for missing native modules.
- Settings dialog with runtime checks; light/dark themes; resizable panes; status
  bar with language, cursor position, indentation and EOL.
- Editor font zoom (`Ctrl+=` / `Ctrl+-` / `Ctrl+0`) persisted across sessions.
- Responsive/reduced-motion CSS and visible focus states.

## Known limitations / not implemented

- No LSP, DAP, merge editor or test explorer. Intentionally out of scope for this
  release; each needs its own integration and tests.
- `fs.watch(..., { recursive: true })` is Windows/macOS-only; on other platforms the
  workspace watcher degrades to no automatic refresh (manual refresh still works).
- Git operations assume credentials are already configured for non-interactive use.
- The integrated terminal relies on the `node-pty` prebuilt binary; a platform or
  Electron version without a matching prebuild needs a C++ toolchain to rebuild.
